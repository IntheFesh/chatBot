# 第 08 轮：时间服务、时区切换、每日计划与生活线生成

> 里程碑：M3 · 前置：第 00–07 轮全绿

## 先读
`CLAUDE.md`；`docs/SPEC.md` R-SCOPE-005/006、§9 作息活动模型、§13 中 R-MEM-002/005、§16 时间与作息运行全部、R-PRO-002（配额在每日计划中生成）、R-LLM-007/008。

## 本轮目标
提供全系统唯一的"现在几点、她现在在干嘛"：按当前机器人时区（默认芝加哥，可切到中国）把她的作息模型落到当地钟点；每天生成一份可复现的日程（起床、入睡、忙碌、饭点、主动次数配额）和她的虚构生活线；正确处理夏令时、时区切换、电脑重启。

## 必须实现的需求
R-SCH-001～005、R-MEM-005（每日生成与一致性检查）、R-MEM-002（每日摘要的触发时间）、R-ACT-001（运行时侧）、R-PRO-002（配额生成部分）、R-SCOPE-005、R-STO-006（本轮的表：`daily_plans`、`timezone_history`）。

## 详细要求

### A. TimeService（R-SCH-001）
1. 依赖第 00 轮 `Clock`；读取运行时设置 `bot_timezone`（订阅第 00 轮的 `state_version` 变化，CLI 或指令改时区后 2 秒内生效）；提供：`now_local()`、`local_date()`、`day_type(local_date)`（节假日按当前 `bot_timezone` 地区：美国用 `holidays.US`，中国用 `chinese_calendar.is_workday()`（含调休），复用第 01/04 轮的同一个日历模块与未收录年份回退）、`her_state(at=None) -> HerState{kind: deep_sleep|sleep_edge|busy|free, until, since, plan_id}`。
2. `her_state` 只依据当天（以及前一天跨午夜部分）的 `daily_plan` 与作息手动修正；不在调用处重新抽样。
3. 替换第 01 轮预算模块使用的临时日期实现为 TimeService（并更新 TRACEABILITY）。

### B. 每日计划（R-SCH-004、R-PRO-002）
1. 生成时机：当地 00:05；启动时若当天计划缺失则立即生成；时区切换时从当前时刻起重建（见 C）。
2. 内容：
   - 起床/入睡时刻：从第 04 轮 `sleep_profile()` 的分布抽样（工作日/周末/节假日分别），手动睡眠修正优先；保证与前一天入睡时刻不冲突（睡眠时长落在她历史分布的 5%–95% 分位之间）。
   - 深睡核心与边缘区间（R-ACT-003 定义）。
   - 忙碌时段：推断的忙碌窗口 + 手动修正（按星期几）；每个忙碌段附该段回复延迟分布引用。
   - 饭点：从她历史中"饭点相关"时段的活跃峰估计（若无法估计用当地常见饭点并标记来源）。
   - 主动配额：在 `[daily_min, daily_max]` 内抽样；抽样分布使均值贴近她真实的"日均先开口次数"（来自画像，样本 7 天时约 3.6），再截断到范围内；`/主动 关` 时为 0。
   - 记录随机种子 = hash(当地日期, 安装随机盐)，便于复现与调试（盐存 keyring 或 settings）。
3. 存 `daily_plans(local_date, timezone, plan_json(enc), seed, created_at, superseded_by)`；`twin plan show [日期]` 输出（当地时间）。

### C. 时区切换（R-SCH-002）
1. API `switch_timezone(new_tz)`：校验 IANA 名称；写 `timezone_history`；从当前时刻起按新时区生成"今天剩余部分"的计划（替代旧计划的剩余部分）。
2. 规则：距离上一次起床问候不足 18 小时则今天不再触发起床问候；若新时区当前处于睡眠区间则立即进入睡眠状态（不跳过睡眠）；已排队的、按旧时区计算的延迟回复与主动候选按绝对时间保留或重算，二选一并写清理由。
3. 指令 `/时区` 在第 11 轮接入本 API；本轮提供 CLI `twin timezone set|show|history`。

### D. 夏令时（R-SCH-003）
- 全部通过 `zoneinfo`；生成计划时用当地钟点再转换为 UTC，处理"不存在的时刻"（春季跳过的 2:xx）与"重复的时刻"（秋季回拨），规则写进文档并测试（芝加哥 2026-03-08、2026-11-01）。

### E. 生活线每日生成与一致性（R-MEM-005）
1. 在她"起床"时刻排队生成当天生活线：输入 = 当天计划（醒/睡/忙/饭点）、最近 3 天生活线、相关真实事实（她的学校/工作/住处等，来自事实库，只用真实来源）、日类型；DeepSeek JSON 输出若干时段事件（活动、地点、心情、细节）。
2. 一致性检查：代码规则（时间不重叠、忙碌时段内的活动与"忙"一致、睡眠时段无活动）+ DeepSeek 对照真实事实与近几天生活线检查矛盾；不通过则带原因重生成一次，仍不通过则采用规则修正后的版本并告警。
3. 写入 `lifeline_events(source=plan)`；查询接口 `lifeline_at(time)` 供回复与主动消息使用。

### F. 每日摘要触发（R-MEM-002）
- 在她起床前 60 分钟（且为 DeepSeek 非高峰时，否则顺延到最近的非高峰窗口，但不晚于起床后 2 小时）排队前一天的 `real`（若当天有导入）与 `bot` 摘要任务。

### G. 重启、中断与睡眠唤醒（R-SCH-005）
- 启动时：载入或生成当天计划；把"计划时刻早于现在的主动候选"标记为过期，不补发；对中断期间到达的用户消息交给引擎正常处理（第 09 轮）。
- 睡眠唤醒（电脑虽设为不休眠，仍可能被手动睡眠或合盖）：`PowerEventMonitor` 组件——Windows 上用隐藏窗口接收 `WM_POWERBROADCAST`（`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC`），并在所有平台上每 tick 比较墙钟与单调时钟的差，跳变超过 2 个 tick 视为发生过挂起；检测到唤醒后执行与重启相同的流程：过期主动候选作废（不补发）、重建当天计划、通知通道组件重连、引擎处理期间到达的消息。非 Windows 平台只用时钟跳变检测（真实实现，不是空函数）。

## 测试要求（全部用注入时钟）
- 不同日类型的计划生成、手动修正优先、睡眠时长约束、配额均值（大量日期抽样的均值接近目标 ±10%）与范围、种子可复现。
- 时区切换：芝加哥 → 上海在多个时刻切换（白天、对方深夜、起床问候刚发过），验证 18 小时规则、睡眠不跳过、计划重建。
- 夏令时两天的计划时刻换算正确、无重复或遗漏的状态区间。
- `her_state` 在一天中各时刻的取值与边界。
- 生活线：规则校验失败的重生成路径、与真实事实冲突被检查出。
- 重启后过期候选不补发。
- 睡眠唤醒：注入时钟模拟墙钟跳变 3 小时 → 触发唤醒流程、过期候选作废、计划重建；Windows 标记测试：向隐藏窗口投递模拟的 `WM_POWERBROADCAST` 消息。
- 调休上班的周末与日历库未收录年份的日类型。
