## 本轮目标
在开始做主动消息之前，先用可复现、有统计意义的方式回答 M1"像不像她"和 M2"记不记得住"，并建立之后全部门槛（M3、M4、M5）共用的评估沙盒与判定框架。门槛不过，就停在本轮改进，不进入第 10 轮。

## 必须实现的需求
R-EVAL-001、R-EVAL-002、R-EVAL-003、R-EVAL-009、R-EVAL-010、R-TRN-013（评估侧：沙盒只经 `AsOfView(t)` 读取）、R-SAFE-006（盲测排除不可复现的样本）、R-LLM-014（评估批量生成按一次性批任务处理）、R-STO-006（本轮的表：`eval_runs`、`eval_items`）。

## 详细要求

### A. 评估沙盒（R-EVAL-009）
1. 把第 09 轮引擎中"组装提示词 → 选定后端生成 → 后处理 → 表情包解析"整理成一个纯流水线 `ReplyPipeline.run(context, data_view) -> ReplyDraft`，线上引擎与沙盒调用**同一个**流水线（重构第 09 轮代码，不复制）；沙盒不经过拟人延迟、发送节奏与通道发送。
2. `InMemoryChannel`：实现 `Channel` 接口的完整内存通道（在 `src/twin/eval/`，有 SPEC 编号 R-EVAL-009，不是测试替身）；沙盒绝不实例化 `IlinkChannel`（有测试）。
3. 写入隔离：沙盒运行时不写 `bot_turns`、`conversation_state`、`proactive_log`、`feedback`、`facts`、`lifeline_events`、`daily_plans`，不触发记忆抽取与学习。允许的写入只有：`eval_runs`、`eval_items`、`cost_ledger`（`purpose=eval`）、`jobs`（历史图片描述排队与批任务记录）、`alerts`、`settings` 中的 `state_version` 与 token 估算校准系数。有测试：运行前后对全部表做行数与校验和快照，变化只出现在上述允许范围内。
4. 两种模式：
   - `holdout`（盲测、留出集风格指标）：时钟注入为样本时刻 t；全部上下文经第 07 轮的 `AsOfView(t)` 读取（pre_holdout 人设卡/画像/作息、as-of 记忆、检索 `before=t`、as-of 表情包与表情代码、她的状态 = `typical_state`、生活线与机器人对话为空）；当地时间按样本当时她所在地的时区；近期对话 = 样本上下文，**所有后端都只给同样的最多 8 个合并轮次**（与 style 后端和训练一致，保证 M5 比较公平）。
   - `live`（记忆测试）：当前时刻、live 数据，但仍然写入隔离。
5. 批量生成是一次性批任务（R-LLM-014）：先给出费用估算，我批准后执行；可续跑。

### B. 盲测（R-EVAL-001）
1. `twin eval blind --backend deepseek|style|hybrid|all --n 50 [--resume <run_id>]`。
2. 抽样：只从留出窗口（`reply_at ≥ holdout_cutoff()`）抽；排除以前任何盲测用过的上下文；排除真实回复中含不可复现行（第 03 轮 `is_reproducible`）的样本；按当地时段（4 档）与会话段长度分层。
3. 生成：每个上下文对每个请求的后端在沙盒 `holdout` 模式下按样本时刻生成一份（style/hybrid 在第 14 轮之后才可用；此前请求它们时明确提示"未部署"）。
4. 统一呈现 `render_candidate()`：真实回复与机器人回复先转成同一种结构（文字行、表情包、表情代码、引用），再用同一个函数渲染——气泡换行；表情包一律显示为"[表情包：<描述>]"（真实的按 md5 查库得描述，机器人的取所选表情包的描述）；引用首行一律"[引用：…]"；表情代码原样。有测试：内容相同的真实回复与机器人回复渲染结果逐字相同。
5. 终端界面（rich）：显示上下文（最近几轮，同样的渲染规则）与 A/B 两条候选（左右随机），按键 `1`/`2` 选"哪条是她"、`s` 跳过、`q` 保存退出；每次判断立即写入 `eval_items`，可续做。
6. 统计：每个后端的猜对率（点估计）、Wilson 95% 置信区间、有效判断数（跳过不计）；后端之间的两比例检验（报告双侧 p 值，并给出 M5 用的单侧 p 值）；按时段与会话长度分组的猜对率。

### C. 风格指标（R-EVAL-002）
- `twin eval style --source live --days 7` 与 `twin eval style --source eval_items --run <id> --backend X`；指标计算复用第 04 轮画像模块的同一批函数（不另写）；live 与 live 画像比、留出集与 pre_holdout 画像比；输出每项相对偏差与是否在 ±30% 内。

### D. 记忆测试（R-EVAL-003）
1. `twin eval memory`：从事实库出 20 题——10 题来源 `real_record`、10 题来源机器人对话（`user_said`/`bot_invented`）；机器人对话来源的可出题事实不足 10 条时，提示"先多聊几天"，本次记为"未通过（样本不足）"，**不用真实记录替补**。题目由 DeepSeek 根据事实改写成我会自然问的问句，并给出标准答案要点。
2. 在沙盒 `live` 模式中提问并取回答；DeepSeek 判分（JSON：correct/partial/wrong + 理由），终端里让我逐题复核、可改判；正确率（partial 记 0.5）≥ 80% 为通过；记录每题证据。

### E. 门槛判定框架（R-EVAL-010）
1. `twin eval gate M0|M1|M2|M3|M4|M5 [--check]`：每个里程碑的判定逻辑以"判定器"形式注册；本轮注册 M0（读取第 01、02 轮存入数据库的探针结果：R-CH-009/010 达标，且 R-LLM-013 按 SPEC 的判定口径通过——①②④ 成功、③ 中 JPEG 与 PNG 成功，其余为记录项）、M1（最近一次盲测中当前默认后端有效判断 ≥ 50 对且猜对率点估计 ≤ 70%）、M2（最近一次记忆测试正确率 ≥ 80% 且来源配比完整）。M3、M4、M5 的判定器分别由第 10、12、14 轮注册；未注册时命令明确输出"该门槛在第 NN 轮接入"并以退出码 2 结束（这是正常的未到阶段状态）。
2. 每次判定把结果、数值、样本数、所用评估运行 id 写入 `eval_runs(kind=gate)`；退出码 0 通过、1 未通过、2 未到阶段；`--check` 只读取最近一次已存结果。
3. 判定口径固定在代码里并有测试；不得为通过门槛而改口径（铁律 12）。

## 测试要求
- 沙盒：只写评估表与费用表（快照比对）；不实例化 `IlinkChannel`；`holdout` 模式的防泄露注入测试（t 之后才出现的事实不在提示词里；检索结果都早于 t；人设卡与画像是 pre_holdout 版本）。
- 线上引擎与沙盒调用同一个 `ReplyPipeline`（结构测试）。
- 盲测：抽样排除规则（用过的上下文、不可复现样本）、分层覆盖、左右随机化（大量抽样下左右比例的二项检验不拒绝 0.5）、`render_candidate()` 同内容同输出、进度保存与续做、跳过不计入。
- 统计：Wilson 区间与两比例检验与已知数值比对（写出公式来源）。
- 风格指标：用合成 `bot_turns` 与 `eval_items` 构造已知偏差，判定正确。
- 记忆测试：来源配比、样本不足判为未通过、partial 计分、复核改判。
- 门槛：M0/M1/M2 判定的通过、未通过、样本不足；`--check`；未注册里程碑退出码 2。
