# 第 10 轮：主动消息（像真人一样随机先找你，不在睡觉时打扰）

> 里程碑：M3（本轮完成后观察 7 天判定门槛）· 前置：第 00–09b 轮全绿，`twin eval gate M1 --check` 与 `twin eval gate M2 --check` 均已通过；第 02 轮 `docs/CHANNEL_REPORT.md` 已给出窗口与条数实测值 · 需要用户：本轮完成后让机器人真实运行 7 天（电脑不休眠，`twin run` 常开），期间正常聊天，周末用 `/评分` 打分

## 先读
`CLAUDE.md`；`docs/SPEC.md` §17 主动消息全部、R-CH-008/009、R-SCH-001/004、R-MEM-005/006、R-ENG-009、R-LLM-008、R-ACT-002/003、R-EVAL-005、R-EVAL-010、§26 M3、`docs/CHANNEL_REPORT.md`。

## 本轮目标
她会在合适的时间、以合适的频率先给用户发消息：起床问候、饭点、睡前、跟进用户说过的事、久没聊时找话题、分享日常；每天次数在范围内随机，睡觉时不发（偶尔"睡不着/刚醒"），不连环轰炸，受平台窗口约束，内容与生活线和记忆一致。

## 必须实现的需求
R-PRO-001～008、R-MEM-006（到期跟进的发送侧）、R-EVAL-005（主动消息审计与 `/评分`）、R-CMD-002（`/评分`）、R-EVAL-010（注册 M3 判定器）、R-SCH-005（主动侧：重启或唤醒后过期候选作废、不补发）、R-STO-006（本轮的表：`proactive_log`、`proactive_candidates`、`ratings`）。

## 详细要求

### A. 调度循环（R-PRO-001/002）
1. `ProactiveScheduler` 组件每 `tick_minutes` 运行一次（时钟对齐到 5 分钟整点 + 每天固定随机偏移，避免与其他任务同时触发）。
2. 非齐次泊松稀释：当天配额 N（来自第 08 轮计划）；把她的先开口率曲线 λ(当地 15 分钟格) 在当天"清醒且非深睡"区间上归一化，使期望次数 = N；每个 tick 以 `1 - exp(-λ·Δt)` 的概率产生"沉默型/分享型"候选。作息型（起床问候、饭点、睡前）与跟进型候选由确定的时间窗产生，计入当天配额；配额用尽后只允许跟进型（且计入当天上限 `daily_max`）。
3. 若用户正在和她聊（引擎状态非 IDLE，或 10 分钟内有往来），本 tick 不产生候选。

### B. 触发类型（R-PRO-004/005）
1. 跟进型：`followups` 中 `due_at` 落入其 `window_minutes` 的条目；问用户结果/关心；发送后标记 done，用户已主动提过则关闭不发。
2. 作息型：起床问候在起床后 5–40 分钟随机（每天最多一次，且受第 08 轮 18 小时规则约束）；饭点在饭点前后 ±30 分钟（概率按她历史在该时段先开口的比例）；睡前在入睡前 15–60 分钟。
3. 沉默型：距上次互动超过从她"沉默后先开口间隔"分布抽样的时长。
4. 分享型：从今天生活线中挑一个尚未分享的片段。
5. 入睡/将醒边缘：在 `sleep_edge` 状态允许以 `p_edge`（她历史深夜/清晨消息频率估计）产生"睡不着/刚醒"类候选，每周不超过 `edge_of_sleep_weekly_max`。
6. 优先级：跟进 > 作息 > 沉默 > 分享；同一 tick 多个候选只取最高优先级。

### C. 硬约束（R-PRO-003）——全部在发送前再检查一次
- `her_state == deep_sleep` → 拒绝（不可配置绕过）；
- 距上一次主动发送 < `min_spacing_min` → 拒绝；
- 用户未回复上一条主动消息时，已追发次数 ≥ `max_chase` → 拒绝；
- `/暂停` 或 `/主动 关` → 拒绝；
- 通道 `can_send_proactive(now, n)` 为假（窗口已过或剩余配额 < 1）→ 拒绝并记录"被窗口抑制"；
- 预算降级级别 ≥ 3 → 拒绝（R-LLM-008）；
- 当天主动次数达到 `daily_max` → 拒绝。
每次拒绝写 `proactive_log`（原因枚举）。

### D. 两步决定（R-PRO-006）
1. 候选通过约束后，调用 DeepSeek（`purpose=proactive`，思考按 `thinking.proactive_planner`，默认开），输入：人设卡（完整版）、当前当地时间与她的状态、今天生活线与已分享片段、记忆块（含待跟进）、最近对话、候选类型与理由、她真实的类似先开口示例（第 05 轮检索，用"先开口"窗口过滤）；JSON 输出 `{send, kind, messages[], sticker_hint, reason}`。
2. `send=false`：记录原因；作息型按窗口剩余时间重排一次，沉默/分享型放弃。
3. `send=true`：内容走第 09 轮的同一后处理流水线（去 AI 腔、事件文字删除、标点、长度、表情包、承诺检测等），再按第 09 轮节奏发送；可多条连发，但条数不超过发送时的 `remaining_quota()`（R-PRO-003）：超出时按第 09 轮同样的规则合并或截短，剩余配额为 0 则不发并记录。
4. 后端为 style/hybrid 时：规划由 DeepSeek 完成，最终文本交风格模型按规划生成（复用 HybridBackend）。
5. 发出后：写 `bot_turns`、`proactive_log`、把提到的生活细节标记为"已分享"并写入生活线（`improvised` 若为新细节）。

### D2. 重启与唤醒（R-SCH-005 的主动侧）
- 订阅第 08 轮的"重启/唤醒"事件：`proactive_candidates` 中计划时刻已过的候选一律标记 `expired`（写 `proactive_log`，原因"中断期间过期"），不补发；起床问候等作息型候选若其时间窗已过则当天不再触发；之后按重建后的计划继续调度。

### E. 与回复引擎的协作
- 主动消息发出后，若用户回复，按普通对话处理；用户在 30 分钟内未回复则计入"未回复"用于追发规则；追发内容要体现"你怎么不理我"之类的自然延续，而非重复。

### F. 审计（R-PRO-008）
- `proactive_log`：候选时刻（UTC 与当地）、类型、是否发送、拒绝原因、她的状态、规划理由（加密）、内容（加密）、追发序号、通道结果。
- `twin proactive log [--days 7]`（只读；不显示正文，除非 `--show-text` 并二次确认）。
- 模拟器放在 `scripts/simulate_proactive.py --days 14`（开发工具，不是 `twin` 子命令）：导入 `tests/support/` 中的假 LLM 与可快进时钟，驱动**生产版**调度器与约束代码跑一个模拟周期，输出统计（每日次数、时段分布、拒绝原因分布），用于调参；生产代码 `src/` 中不出现任何假模型（CLAUDE.md 铁律 2）。

### G. `/评分` 与主动消息审计（R-EVAL-005、R-CMD-002）
1. `/评分 <1-5> [备注]`：写 `ratings`（时间、分数、备注加密）；以"⚙️"系统口吻立即回复，不进入记忆、学习与检索；第 11 轮的完整指令解析器会接管它的解析（复用本轮的处理函数）。
2. `twin eval proactive --days 7`：基于 `proactive_log` 统计深睡核心时段发送数（必须 0）、每天次数是否在范围内、最小间隔与追发违规数、边缘消息每周次数、被窗口抑制次数、该周 `/评分` 平均分；输出按当地时间的发送时刻分布（文字表格），结果写 `eval_runs(kind=proactive_audit)`。
3. 注册 M3 判定器（第 09b 轮的框架）：最近连续 7 个当地日的审计全部合规（深睡 0 次、每天在范围内、间隔与追发零违规、边缘 ≤ 上限）且这 7 天内至少有一次 `/评分`、平均 ≥ 4；不足 7 天时判为"观察期未满"（退出码 1，并显示还差几天）。

## 测试要求（注入时钟 + 固定种子 + 假 DeepSeek）
- 模拟 30 天：深睡时段 0 次；每天次数在 `[daily_min, daily_max]`；日均值与目标误差 ≤ 15%；间隔与追发规则零违规；边缘消息每周 ≤ 2 次。
- 每条硬约束各一个拒绝用例，且拒绝写入日志原因正确。
- 窗口抑制：模拟用户 23 小时未发消息 → 不发；用户发一条后恢复。
- 重启与唤醒：墙钟跳过起床问候时间窗 → 候选过期、当天不补发。
- 跟进型：到期发送、用户已提过则关闭。
- 时区切换当天（芝加哥 → 上海）不重复起床问候、不在新时区深睡时发送。
- `send=false` 的重排与放弃逻辑；内容经过后处理（承诺句式被拦截）。
- 配额：剩余配额小于规划条数时截短，为 0 时不发并记录原因。
- `/评分` 写入与范围校验；审计各统计项（用模拟器产出的日志 + 人工构造的违规日志）；M3 判定器的通过、违规、观察期未满、缺评分。
