# wechat-twin · Claude Code 多轮提示词包

用 Claude Code 从零实现产品文档《微信拟人聊天机器人 · 产品文档》中的全部功能。共 18 轮（00–16，外加 09b），每轮一个提示词文件，按顺序执行。产品文档里"每个阶段过关后再进下一个"落实为各轮末尾的**门槛检查**：不过关就停在该轮改进。

## 包里有什么

| 文件 | 作用 |
| --- | --- |
| `CLAUDE.md` | 放在仓库根目录。Claude Code 每次会话自动读取的项目规则（铁律、技术栈、目录、命令、汇报格式）。 |
| `docs/SPEC.md` | 技术规格，唯一事实源。195 条需求，编号 `R-<模块>-<序号>`。 |
| `docs/TRACEABILITY.md` | 表 1：产品文档 105 个需求点 → SPEC 编号 → 轮次；表 2：每条 SPEC 需求的负责轮次、状态、实现位置、测试（由 Claude Code 每轮填写，`scripts/trace_check.py` 自动核对）。 |
| `prompts/00`–`16`、`09b` | 每轮的提示词。 |

## 怎么用

1. 在 Windows 上准备：Git、[uv](https://docs.astral.sh/uv/)、Node.js（第 02 轮获取官方协议源码用）、Claude Code。
2. 新建空目录并初始化仓库：
   ```powershell
   mkdir wechat-twin; cd wechat-twin; git init
   ```
3. 把本包的 `CLAUDE.md`、`docs/`、`prompts/` 复制进去，先提交一次。
4. 在该目录启动 `claude`。每一轮：
   - 先按 Shift+Tab 切到计划模式；
   - 输入：`执行 @prompts/00-bootstrap.md`（换成当前轮次的文件；09 之后是 `09b-eval-gates.md`）；
   - 审阅它的计划，确认后让它实现；
   - 它汇报后，自己跑一遍提示词里的"验收"命令；
   - 确认 `uv run python scripts/trace_check.py --round NN`（如 `--round 09b`）全绿、提示词里的门槛检查已通过后 `git commit`；
   - 用 `/clear` 清空上下文，再开始下一轮。
5. 不要跳轮，不要并行执行多轮。某轮没过验收或门槛就留在该轮修。第 10、12 轮各有 7 天观察期，期间机器人正常运行，你正常和她聊天即可。

## 几条重要约定

- **真实聊天数据永远不放进仓库。** 导出目录在配置里指向仓库外的路径；测试只用合成数据。
- **第 02 轮协议文档写完会先停下来**等你确认；**第 02 轮实测如果主动窗口不达标也会停下来**，那时再决定是否改走企业微信。
- **第 03 轮先跑 `twin import inspect`**：它只输出导出目录的结构（键名、类型、计数），不含任何内容；把报告给 Claude Code 核对字段后再导入。
- **第 04 轮会请你确认她的睡眠时段**：7 天样本里有几个低谷，推断结果不对就用作息修正。
- **一次性的大额调用**（全量记忆回放、首次批量看图与打标签、人设卡生成等）会先给出费用估算，你 `twin jobs approve` 之后才执行，不占用每天 1 美元的日常预算。
- **第 13 轮训练前**，Claude Code 会联网核对 LLaMA-Factory、Blackwell（sm_120）对 PyTorch 与 CUDA 版本的要求、AutoDL 环境，再动手。RTX 5090 与 RTX PRO 6000 都是 Blackwell 架构，需要 CUDA 12.8 版的 PyTorch 2.7 及以上。AutoDL 默认数据盘 50GB 不够，租卡时按档位扩容（8B ≥ 70GB、14B ≥ 110GB、32B ≥ 230GB）。
- **风格模型只有盲测胜过纯 DeepSeek 后端、且留出集风格指标达标才会被设为默认**，否则继续用 DeepSeek。训练与线上推理用同一套模板代码，逐 token 核对；训练和评估只能看到样本当时已知的信息。
- SPEC 与现实不符时，Claude Code 会先停下来说明，而不是自己降级需求。
